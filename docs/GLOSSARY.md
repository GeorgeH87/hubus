# Glossary

## Terms

- **MCID**: Master Communication ID. The unique identifier used for arbitration and addressing. Valid range `1..63` in v0; `0` is reserved.
- **Priority**: The rule that higher MCID values win arbitration in v0. Within a burst it determines only the order of service.
- **State**: The live data a slave exposes for `REQUEST_STATE` (for example the level of every button). Read at any time, never cleared. Not to be confused with the event buffer.
- **Event Buffer**: The single outgoing buffer of a slave for changes and messages (`REQUEST_DATA`). Cleared after delivery.
- **Burst**: A sequence of group `REQUEST_DATA` transactions that serves every slave pending at its start, in descending MCID order. Each transaction's arbitration winner sends its data directly.
- **Group Request**: `REQUEST_INFO` or `REQUEST_DATA` with `TARGET_LEN < 6`. The matching slaves arbitrate and the winner answers in the same transaction.
- **Handoff Slot**: The slot following each arbitration bit. A slave that lost at exactly that bit pulls `DATA` low in it, telling the master that a further matching slave exists in the corresponding prefix group.
- **Pending Mask**: A prefix mask (`MCID` prefix + `TARGET_LEN`) derived by the master from a low handoff slot. It identifies a group containing at least one slave that can answer.
- **Pending Mask Stack**: Master-internal last-in-first-out list of masks still to be requested in the current burst or scan. Never transmitted.
- **Slave Buffer**: The single outgoing buffer of a slave. Holds event data or a captured status until the master retrieves it with `REQUEST_DATA`. Writing it sets the pending flag.
- **STATUS_CAPTURE**: Protocol opcode `0x00` of `SEND_COMMAND`. Asks one or more slaves to write their current status into the slave buffer.
- **Slave Info**: Static device metadata (protocol version, capabilities, application data) returned on `REQUEST_INFO`.
- **Fire-and-Forget**: Commands are never acknowledged. The master verifies a state by reading it back.
- **Overwrite Policy**: The rule that new slave buffer content (event data or captured status) may replace unread older content.
- **Target Mask Addressing**: Unified addressing mode where master commands provide an `MCID` prefix plus `TARGET_LEN` and all matching slaves are addressed. With `TARGET_LEN < 6` it is strictly one-way (master to n slaves, no response frames).
- **Return Path**: The only way a slave reports on its own initiative: set the pending flag, announce via idle event handshake, and get served in a burst.
- **Prefix Match**: A slave matches when its most-significant `TARGET_LEN` MCID bits equal the command prefix.
- **START Condition**: `DATA` falls while `CLK` is high. Generated by the master to begin a frame; resynchronizes all slaves.
- **STOP Condition**: `DATA` rises while `CLK` is high. Generated by the master to end a frame; bus returns to idle.
- **RESET**: START immediately followed by STOP. Resets the slave communication stack while preserving buffered data and the pending flag.
- **Accepted Rare Case**: A known corner-case failure that is tolerated because it is rare and recovers at the next master cycle.
- **Generation Counter (`GEN`)**: Mandatory 2-bit counter in the `SLAVE_DATA` header, incremented on every slave buffer write. Lets the master detect duplicates and overwritten content.
- **MORE Flag**: Bit in the `SLAVE_DATA` header set by the application when further fragments of a larger dataset follow.
