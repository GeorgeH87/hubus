# Glossary

| Term | Meaning | Defined in |
|---|---|---|
| Arbitration | Bit by bit contest of the slaves that can answer a group request; the higher MCID wins. | [§5](spec/05-arbitration.md) |
| Blind section | Bounded time after a command in which a slave handles no edges, for timing-critical application code; announced as the blind class in `SLAVE_INFO` byte 3. The slave resynchronizes at its end, and the master keeps away from it meanwhile. | [§7.8](spec/07-slave.md#78-blind-sections) |
| Burst | Sequence of group `REQUEST_DATA` transactions that serves every slave pending at its start, in descending MCID order, one transaction per slave. | [§6.2](spec/06-operation.md#62-burst) |
| Contender | A slave that matches a group request and can answer it, and therefore arbitrates. | [§5.2](spec/05-arbitration.md#52-contenders) |
| Event buffer | The single outgoing buffer of a slave for changes and messages, read with `REQUEST_DATA` and cleared after delivery. Optional. | [§4.8](spec/04-frames.md#48-event-buffer) |
| Fire-and-forget | Commands are never acknowledged; the master verifies a state by reading it back. | [§4.4](spec/04-frames.md#44-command-opcodes) |
| `GEN` | 2-bit generation counter in the header of event frames; lets the master detect duplicates and overwritten content. | [§4.9](spec/04-frames.md#49-generation-counter-gen) |
| Group request | `REQUEST_STATE`, `REQUEST_INFO`, or `REQUEST_DATA` with `TARGET_LEN < 6`: the matching slaves that can answer arbitrate, and the winner answers in the same transaction. | [§4.5](spec/04-frames.md#45-addressing) |
| Handoff slot | The slot after each arbitration bit, pulled low by the slaves that lost at exactly that bit; tells the master where further contenders are. | [§5.3](spec/05-arbitration.md#53-slot-sequence) |
| Hardware identifier (HWID) | What a slave is, in `SLAVE_INFO` from byte 2: type, then for types `0x80..0xFE` variant, version, hardware revision, and an optional serial number. Independent of the MCID; selects the master module by prefix or mask. | [§4.7](spec/04-frames.md#hardware-identifier-hwid) |
| Idle event handshake | A slave pulls `DATA` low on the idle bus; the master confirms with a clock pulse and starts a burst. | [§6.1](spec/06-operation.md#61-idle-event-handshake) |
| Info page | Last page of the application area on a slave with firmware update: length, CRC-16, and entry of the application; the updater starts only an application it describes. | [§6.8](spec/06-operation.md#68-firmware-update) |
| Line condition | START, STOP, or RESET: a `DATA` change while `CLK` is high, generated by the master. | [§2.1](spec/02-line-conditions.md#21-conditions) |
| MCID | Master communication ID: the 6-bit address of a slave, `1..63`; `0` is reserved. | [§4.5](spec/04-frames.md#45-addressing) |
| `MORE` | Header bit of an event frame: further fragments follow. | [§4.11](spec/04-frames.md#411-fragments) |
| Optional parts | Event buffer and state (a slave may have either, both, or neither), and firmware update for devices with enough flash. | [§7.4](spec/07-slave.md#74-optional-parts) |
| Pending flag | Set when the event buffer is written, cleared after delivery; a pending slave announces itself and contends in bursts. | [§4.8](spec/04-frames.md#48-event-buffer) |
| Pending mask | A prefix mask (`MCID` prefix and `TARGET_LEN`) derived from a low handoff slot; a group with at least one further contender. | [§5.5](spec/05-arbitration.md#55-pending-masks) |
| Pending mask stack | Master-internal last-in-first-out list of pending masks; never transmitted. | [§5.5](spec/05-arbitration.md#55-pending-masks) |
| RESET | START immediately followed by STOP; resets the communication stack of every slave but keeps buffered data and the pending flag. | [§6.5](spec/06-operation.md#65-communication-stack-reset) |
| `SLAVE_INFO` | Static device information: protocol version, capabilities, accepted command size, speed and blind class, application bytes. | [§4.7](spec/04-frames.md#47-slave-info-slave_info) |
| Speed class | `0..15` in `SLAVE_INFO` byte 3: the edge response time a slave firmware guarantees; `0` = not declared. The master derives its timing minimums from it. | [§1.5](spec/01-physical-layer.md#15-speed-classes) |
| State | Live data a slave exposes for `REQUEST_STATE`, for example the level of every input; read at any time, never cleared. Optional. | [§4.10](spec/04-frames.md#410-state) |
| `STATUS_CAPTURE` | Command opcode `0x00`: the slave writes its current status into its event buffer. | [§4.4](spec/04-frames.md#44-command-opcodes) |
| Target mask | `TARGET_LEN` significant prefix bits of the `MCID` field that select the addressed slaves. | [§4.5](spec/04-frames.md#45-addressing) |
| Turnaround slot | One clock period with `DATA` released between the master frame and the slave's transmission. | [§3.2](spec/03-transactions.md#32-turnaround-slot) |
| Updater | Second firmware on a slave with firmware update: takes a new application page by page over the bus and starts it if it checks out. Capability bit 4. | [§6.8](spec/06-operation.md#68-firmware-update) |
| Accepted rare case | A known corner case that is tolerated because it is rare and recovers at the next master cycle. | [§8](spec/08-faults.md) |
